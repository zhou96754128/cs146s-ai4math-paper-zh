## 二、逐日记录

### 2026-09-15 · 环境与选题

**任务**：让 LaTeX 能编译中文论文；确定选题。

**AI 协作**：AI 先提议"装 MacTeX/brew 装 texlive"，实测本机无 `pdflatex` / `xelatex` / `tectonic`，且 `brew` 也不存在 → 该方案作废。AI 改提"下载 tectonic 独立二进制（自带宏包与字体，无需包管理器）"。实测下载 `tectonic-0.17.0-aarch64-apple-darwin.tar.gz`（21704674 B）到 `/Users/xiaowo/.cache/c2latex/`，二进制 53998928 B，版本 `Tectonic 0.17.0`。

**人工核验**：
- 英文最小样例编译成功（`_smoke/min.pdf` = 32598 B）；
- 中文最小样例初版失败（缺中文字体），改用 `\documentclass[11pt,fontset=fandol]{ctexart}` 后成功（`_smoke/min-zh-fandol.pdf` = 29857 B）。
- 结论：编译链可用，论文正文用 ctexart + fandol 字体集。

**AI 判断的边界**：AI 无法在本机做视觉检查（无图像识别输入），因此"PDF 好不好看"不能由 AI 断言，只能由结构探针 + 人工确认。

### 2026-09-16 · 文献检索与真伪核验（本次最关键的一段）

**任务**：满足"≥8 篇真实可查一手文献"且不触"引用造假"红线。

**AI 协作**：AI 没有直接凭记忆列参考文献，而是写了一个可复跑的核验脚本 `pipeline/verify_refs.py`：
- 用 arXiv API（`export.arxiv.org/api/query?id_list=`，按 ID 精确查询）与 Crossref API（`api.crossref.org/works?query.bibliographic=`）双向核验；
- **只有命中者才进入 `references.bib`**，未命中进入"未能核验"清单；
- 产出三份可审计文件：`lit/refs.json`（结构化结果）、`lit/参考文献核验记录.md`（人读版）、`lit/references-verified.bib`（仅通过核验的条目）。
- 终态：31 条全部核验通过，未核验 0 条。

**人工核验与纠错（AI 出错并被抓出的地方）**：
1. **脚本崩溃**：生成报告时用 `"% 生成时间：%s" % ...`，中文"生"字紧跟在 `%` 之后被当成格式符，抛 `ValueError: unsupported format character '?' (0x751f)`。→ 改为字符串拼接 `"% 生成时间：" + ...`，脚本复跑通过。
2. **核验阈值过松**：Crossref 标题模糊匹配初版把相似度 0.75–0.80 的结果也算命中，抽查发现是"标题像但不是同一篇"。→ 收紧为只信 `sim=1.00` 的精确命中，宁缺毋滥。
3. **arXiv 编号写错**：一条记录的 arXiv 号一度写成 2205.12950（与真实论文无关），核对 `id_list` 返回后改为正确编号。

**AI 结论人工核验原则（本次执行）**：AI 给的每一条"这篇文献说了 X"，都要回到条目标题/出处确认 X 与之匹配；不能只确认"文献存在"就放行。

### 2026-09-16 · 写作与"引用—主张"逐条核验

**任务**：把框架写成 9 节论文，并让每一条引用都真的支撑它所在的那句话。

**AI 协作**：AI 负责起草段落并给出引用位置；人工负责质疑"这句引用放这儿对不对"。

**核验方法**：把 `references.bib` 的 31 个条目导出为"bib key → 标题/年份/出处"清单，逐条与正文语境对照。结果抓出 **4 处错配**，全部修正：

| # | 引用 | AI 原本的主张 | 条目的真实内容 | 处理 |
|---|---|---|---|---|
| 1 | `thakur2023context` | "把新问题的解法检索复用于类似问题" | *An In-Context Learning Agent for Formal Theorem-Proving*（上下文学习定理证明智能体） | 删除该处引用；改放到"把定理证明组织为上下文学习智能体的交互过程"一句 |
| 2 | `ni2023evaluating` | "数据污染会抬高分数" | *Evaluating the Robustness to Instructions of LLMs*（指令鲁棒性） | 拆开：污染句只留 `sainz2023nlp`，`ni2023evaluating` 独立支持"指令措辞变化会影响表现" |
| 3 | `zhou2023solving` | "把复杂问题显式分解并按难度排序求解" | *…GPT-4 Code Interpreter with Code-based Self-Verification*（代码解释器 + 代码级自验证） | 改写为"把推理与代码执行、结果自核验结合"；讨论节中从"生成式推理路线"移入"工具增强路线" |
| 4 | `zhou2024don` | 全库有一条条目从未被正文引用 | *Don't Trust: Verify*（自动形式化落地） | 补引到自动形式化句，消除"未引用条目" |

**这次犯错的类型**：第 3 条是典型的**"凭语义记忆配引用"**——一看到"分解并按难度排序"就想到 least-to-most，于是顺手挂上了一个 key 里带 2023 的 Zhou 条目，但条目其实是另一篇。AI 的语义联想是对的，**连接错了**。对策已固化进流程：引用核验不看"关键词像不像"，只看"导出的标题清单里，这一条的标题是否字面支持这句话"。

### 2026-09-16 · 编译排错与终态验收

**AI 协作**：AI 负责读日志定位错误，人工负责复跑确认。

- 错误 1：`Illegal, another \bibstyle command---line 136 of file paper.aux` → `paper.tex` 里 `\bibliographystyle` 重复设置，删掉多余一处。

**必须写明的核验局限（诚实记录）**：
1. 本机 AI 无视觉输入能力，**PDF 版式无法由 AI 肉眼确认**。替代做法是用 PyMuPDF 做结构探针：逐页统计矢量图形/图像数量、文本包围盒是否越界、图/表标题落在第几页。探针显示 图1→p5、表1→p6、图2→p7、表2→p7、表3→p9，文本未越界。**"没发现问题"不等于"排版没问题"**。
2. 存在 2 处 Underfull \hbox（`parts/05-failure:24`、`parts/06-metrics:21`），属排版松散警告，不影响可编译性与可读性，未强行修改（避免为消警告破坏语义）。
3. 论文未做真实系统实验，指标为定义与可计算性论证，不构成规模经验主张——此边界已在正文与 AAR 中显式声明。

## 三、AI 使用原则小结

1. **不让 AI 直接产出参考文献表**：所有条目必须过一遍 arXiv / Crossref 的机器核验，命中才入库。
2. **不让"文献存在"冒充"文献支持"**：引用核验比的是标题与主张的字面匹配。
3. **AI 的自我判断不作为验收依据**：编译是否通过、引用是否闭环，一律用命令与脚本的真实输出判定。
4. **AI 的能力边界写入交付物**：无视觉、无实验条件这两条局限，宁可写进日志与 AAR，也不装作已经验证过。
